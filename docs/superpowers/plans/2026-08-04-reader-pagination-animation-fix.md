# Reader 分页饱满度与翻页冲突修复记录

## 问题与根因

分页器原先把 `Range.getClientRects()` 返回的字形矩形高度当成 CSS 行高。字形高度通常小于真实行盒高度，后续又用这些高度累加分页预算、切片高度和纵向位移，导致测量坐标与实际渲染坐标逐页偏离。测量节点与显示节点的外边距折叠规则也不一致，因此会出现“计算已经填满、页面仍有明显留白”。

翻页交互同时存在三个进度来源：点击补间、拖动跟手和新的指针手势。动画尚未结束时，新手势仍能进入并写入相同页面层的 `transform`；短距离或错误轴向的拖动还可能退化成中央点击，触发工具栏。`none` 模式也错误地创建双层动画并等待补间结束。

## 已实施方案

### 分页

- 桌面端翻页文章建立明确的动态视口高度，修复父布局在 `md` 断点变为自然高度后分页器坍缩为 `0px` 的问题。
- 以相邻视觉行之间的真实边界建立 `lineOffsets`，分页预算、裁切高度和位移统一使用同一坐标系。
- 首尾边界包含块自身的排版空间和段落间距，不再重复追加 `margin-bottom`。
- 测量与显示节点统一使用独立格式化上下文，避免段落外边距折叠方式不同。
- 仍保留行级跨页切片，普通页面尽可能容纳完整行；章节最后一页允许自然留白。

### 手势与动画

- 保留 `simulate`、`cover`、`slide`、`vertical` 和 `none` 全部模式。
- 覆盖和平移动画为移动页增加方向对应的边线与投影，使同色页面也有清晰分界；平移旧页也保留轻微层次阴影。
- 仿真书脊以正文阅读区域边缘为轴，而不是以居中的文字容器边缘为轴；上一页使用阅读区域右边缘。
- 跨章边界先完成当前动画，再请求相邻章节；目标章节第一页使用零基页码 `0`，避免错误落到第二页。
- 补间运行期间不允许新的拖动进度与其竞争。
- 手势超过阈值后锁定主轴；错误轴向移动直接取消，不再退化成工具栏点击。
- `pointerup` 阻止兼容性点击，避免中央点击显示工具栏后，同一次物理点击继续命中新出现的控件。
- 交互元素不进入正文翻页手势。
- `none` 模式直接提交新页，不创建双层页面或等待动画。
- 仿真翻页增加 3D 保持上下文，并按前后方向使用正确的翻页轴。

### 排版安全

- 当相邻字形矩形发生重叠时，切片边界退回相邻行起点的中线，避免边界落进下一行字形内部。
- 切片高度继续向上取整，避免亚像素高度把页底文字削掉。
- 默认段间距由 `1em` 收紧到 `0.5em`，可调范围扩展为 `0–1.5em`；段落上边距保持为零，避免双边距叠加。

## 验收范围

- 左、中、右三区点击职责互斥。
- 横向动画不响应纵向误触，纵向动画不应响应横向误触。
- 拖动经过中央区域不显示或隐藏工具栏。
- 动画和拖动不会同时修改翻页进度。
- 五种模式均可前后翻页；无动画模式即时完成。
- 分页切片的测量高度、显示高度和位移来自同一组边界。
- Reader 全量测试、TypeScript 编译和生产构建通过。
